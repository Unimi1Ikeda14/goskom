# GosKom — Цифровая платформа коммунальных услуг

**GosKom** — это динамическое веб-приложение, представляющее собой единую экосистему для управления жилищно-коммунальными услугами. Платформа призвана автоматизировать взаимодействие жителей с управляющими компаниями, предоставляя инструменты для моментальной оплаты счетов, передачи показаний приборов учета и мониторинга состояния сетей в реальном времени. Основная цель проекта — сделать сферу ЖКХ прозрачной и доступной, избавляя пользователя от необходимости личного посещения офисов и бумажной волокиты.

**Целевая аудитория:** Собственники и арендаторы жилья, стремящиеся к цифровому контролю расходов, а также сотрудники диспетчерских служб, которым необходим оперативный канал информирования граждан об аварийных ситуациях.

### Ключевой функционал
* **Централизованный биллинг:** Автоматическое формирование счетов администратором и удобный просмотр истории начислений жильцами.
* **Передача показаний:** Интеллектуальная форма подачи данных счетчиков по четырем типам ресурсов (ГВС, ХВС, свет, газ) с валидацией данных.
* **Мониторинг инфраструктуры:** Список актуальных плановых и аварийных отключений (свет, вода, газ, отопление) с визуальной маркировкой экстренных ситуаций.
* **Инфо-центр:** Лента официальных новостей ЖКХ и объявлений от администрации с возможностью публикации анонсов и медиафайлов.
* **Техническая поддержка:** Система подачи заявок жильцов на ремонт и отслеживание их статуса («НОВАЯ», «В_РАБОТЕ», «ЗАВЕРШЕНА») в режиме онлайн.
* **Панель администратора:** Полноценный интерфейс для управления пользователями, автоматического расчета тарифов, выставления квитанций и публикации новостей/отключений.

## 1. Структура приложения и маршрутизация (SPA-компоненты через HTMX)

Все страницы и формы личного кабинета и панели управления загружаются динамически без полной перезагрузки браузера благодаря интеграции **HTMX** (замена контента внутри блока `#main-content`).

| № | Раздел | Маршрут (URL) | Тип доступа | Описание |
|---|---|---|---|---|
| 1 | Главная страница | `/welcome` или `/` | Публичный | Лендинг с анонсами новостей и быстрыми ссылками. |
| 2 | Аутентификация | `/login`, `/register` | Публичный | Вход и регистрация пользователей. |
| 3 | Личный кабинет | `/profile` | Приватный (`USER`, `ADMIN`) | Профиль жильца: баланс, список квитанций, быстрые виджеты. |
| 4 | Детали счета | `/profile/billing/{id}`| Приватный (`USER`, `ADMIN`) | Подробная квитанция с расшифровкой услуг, тарифов и кнопкой оплаты. |
| 5 | Приборы учета | `/meters` | Приватный (`USER`) | Интерфейс ввода текущих показаний счетчиков (карточки ресурсов). |
| 6 | История показаний | `/meters/history` | Приватный (`USER`) | Архивный журнал отправленных данных с фильтром по ресурсу. |
| 7 | Панель администратора| `/admin` | Приватный (`ADMIN`) | Управление жильцами, выписка жировок, публикация новостей/ремонтов. |
| 8 | Центр поддержки | `/support` | Приватный (`USER`) | Список обращений в диспетчерскую службу с текущими статусами. |
| 9 | Создание заявки | `/support/create` | Приватный (`USER`) | Форма подачи обращения по категориям неисправностей. |

## 2. Технологический стек

### Backend & Frontend (Monolith SSR + HTMX SPA)
* **Java (Spring Boot 3.x):** Основной бэкенд-стек. Обеспечивает надежную бизнес-логику, безопасную обработку транзакций и авторизацию пользователей.
* **Spring Security:** Отвечает за разграничение прав доступа. Безопасность усилена сквозной валидацией **CSRF-токенов**, которые динамически инжектируются во все асинхронные HTTP-запросы.
* **Thymeleaf:** Серверный шаблонизатор, разбитый на изолированные фрагменты (`th:fragment`). Позволяет генерировать как полные страницы, так и отдельные HTML-кусочки для динамических обновлений.
* **HTMX:** Движок фронтенда. Используется для отказа от тяжелых JS-фреймворков. Заменяет стандартные переходы по ссылкам и отправку форм на AJAX-запросы (`hx-get`, `hx-post`, `hx-delete`), обеспечивая скорость работы приложения на уровне Single Page Application (SPA).
* **Глобальный адаптивный CSS:** Все стили приложения изолированы в едином внешнем файле (`/css/style.css`). Стили полностью избавлены от жестких inline-свойств и переписаны с использованием **Flexbox** и адаптивных медиа-запросов (`@media`), что гарантирует корректное отображение таблиц, жировок и форм на экранах любых мобильных телефонов.

### База данных
* **SQLite:** Компактная реляционная СУБД. Хранит данные в одном файле внутри проекта, идеальна для быстрой разработки и развертывания без необходимости администрирования тяжелых серверов баз данных.

### Инфраструктура
* **Maven:** Сборка проекта, управление зависимостями и плагинами.
* **Spring Data JPA:** Объектно-реляционное отображение (ORM) над базой данных SQLite для прозрачной работы с репозиториями на уровне Java-интерфейсов.

## 3. Визуальное проектирование и UI-компоненты

### Главный макет (`index.html`)
* **Навигационная панель (`.navbar`):** Адаптивная шапка сайта. На десктопах отображает логотип, ссылки разделов и блок пользователя (Имя, аватар, кнопка «Выйти») в один ряд. На смартфонах автоматически перестраивается в компактный вертикальный стек элементов по центру экрана.
* **Контейнер содержимого (`#main-content`):** Целевая зона для HTMX. Вся динамика сайта (переключение на квитанции, открытие админки, отправка счетчиков) летит сюда без перезагрузки страницы.

### Панель управления администратора (`/admin`)
* **Форма выставления квитанций:** Интерактивный блок. Выбор жильца или типа коммунальной услуги автоматически триггерит HTMX-запрос `/admin/calculate-amount` для фонового расчета рекомендуемой суммы на основе текущих тарифов.
* **Таблица пользователей (`.goskom-table`):** На десктопе — классическая таблица. На экранах мобильных устройств (менее 850px) скрывает `<thead>` и трансформирует каждую строку в отдельную независимую карточку, где заголовки колонок подставляются слева через CSS-свойство `content: attr(data-label)`.

### Страница детализации квитанции (`/profile/billing/{id}`)
* **Блок квитанции (`.bill-summary-box`):** Фирменный чек с цветовой индикацией статуса («ОПЛАЧЕНО» — зеленый, «НЕ ОПЛАЧЕНО» — красный). На смартфонах перестраивается в вертикальный блок, адаптируя размеры шрифтов и растягивая кнопку оплаты на весь экран для удобного нажатия пальцем.

### Приборы учета и архив (`/meters`, `/meters/history`)
* **Формы счетчиков (`.meter-card-form`):** Список ресурсов (ХВС, ГВС, Свет, Газ) в виде аккуратных строк с иконками. При сужении экрана инпуты ввода новых данных и кнопки отправки автоматически масштабируются и занимают 100% ширины карточки.

## 4. Полная схема данных и архитектура контроллеров

### 4.1. Модели данных (Сущности JPA и Enum)

В приложении используется реляционная структура данных. Связи между таблицами настроены на уровне JPA-аннотаций через внешние ключи (Foreign Keys) с поддержкой каскадного удаления зависимых записей при удалении пользователя.

#### 1. Перечисление `BillType` (Enum)
Определяет категорию коммунального ресурса, сквозные тарифные ставки и визуальные маркеры (иконки):
* `HOT_WATER` (Горячее водоснабжение — м³)
* `COLD_WATER` (Холодное водоснабжение — м³)
* `ELECTRICITY` (Электроэнергия — кВт/ч)
* `GAS` (Газоснабжение — м³)
* `HEATING` (Отопление — фиксированная ставка / м²)

#### 2. Сущность `User` (Таблица пользователей)
Описывает учетные данные жильцов и администраторов, а также хранит текущее (последнее зафиксированное) состояние приборов учета.
* `id` (Long, Primary Key, Autoincrement) — уникальный идентификатор.
* `name` (String, Not Null) — ФИО жильца или имя администратора.
* `email` (String, Unique, Not Null) — электронная почта (логин в системе).
* `password` (String, Not Null) — хешированная строка пароля (BCrypt).
* `role` (String, Not Null) — уровень доступа: `USER` (жилец) или `ADMIN` (сотрудник ЖКХ).
* `hotWater` (Double) — актуальное кубическое значение счетчика горячей воды.
* `coldWater` (Double) — актуальное кубическое значение счетчика холодной воды.
* `electricity` (Integer) — актуальное значение счетчика электроэнергии в кВт/ч.
* `gas` (Double) — актуальное кубическое значение счетчика газа.

#### 3. Сущность `Bill` (Таблица квитанций / жировок)
Хранит информацию о начислениях за коммунальные услуги, привязанных к конкретному пользователю.
* `id` (Long, Primary Key, Autoincrement) — уникальный идентификатор счета.
* `residentId` (Long, Foreign Key, Not Null) — указывает на `User.id` (владельца счета). Связь `@ManyToOne`.
* `type` (Enum `BillType`, Not Null) — категория услуги, за которую сформирован счет.
* `amount` (Double, Not Null) — итоговая сумма к оплате в белорусских рублях (BYN).
* `paid` (Boolean, Default: false) — флаг статуса оплаты счета (Оплачено / Не оплачено).
* `createdAt` (LocalDateTime, Not Null) — дата и время автоматического или ручного формирования квитанции.
* `paidAt` (LocalDateTime, Nullable) — точное время совершения транзакции (заполняется строго после успешной оплаты).

#### 4. Сущность `MeterReading` (Таблица истории показаний)
Служит историческим архивом для генерации графиков, отчетов и вычисления ежемесячного чистого расхода ресурсов.
* `id` (Long, Primary Key, Autoincrement) — идентификатор записи в журнале.
* `residentId` (Long, Foreign Key, Not Null) — указывает на `User.id` (кто отправил данные). Связь `@ManyToOne`.
* `type` (Enum `BillType`, Not Null) — тип прибора учета.
* `value` (Double, Not Null) — переданное числовое значение на момент подачи.
* `consumption` (Double, Not Null) — автоматически вычисляемый чистый расход (разница между текущим введенным значением и предыдущим значением из `User`).
* `createdAt` (LocalDateTime, Not Null) — дата и время отправки данных в диспетчерскую.

### 4.2. Архитектура эндпоинтов и контроллеров

**1. Main & Auth (Маршрутизация интерфейса)**
* `GET /` или `/welcome` — отдает фрагмент главной страницы.
* `GET /login` / `GET /register` — загрузка адаптивных форм авторизации и регистрации.
* `POST /login` — обработка аутентификации средствами Spring Security.

**2. Profile & Billing Controller (Личный кабинет жильца)**
* `GET /profile` — загрузка ЛК, передача списков актуальных квитанций жильца.
* `GET /profile/billing/{id}` — загрузка детального интерфейса жировки №id.
* `POST /profile/pay-bill/{id}` — проведение оплаты, обновление флага `paid = true` и фиксация времени `paidAt`.

**3. Meter Controller (Учет ресурсов)**
* `GET /meters` — вызов карточек для ввода текущих кубов и киловатт.
* `POST /meters/submit` — обработка новых показаний, расчет дельты расхода (`consumption`) и сохранение в архив.
* `GET /meters/history` — загрузка таблицы архива с поддержкой фильтрации по типу ресурса через параметр `?historyType=...`.

**4. Admin Controller (Управление системой)**
* `GET /admin` — открытие панели управления, выгрузка списков всех жильцов.
* `GET /admin/calculate-amount` — фоновый расчет стоимости услуги на лету при изменении селектов формы.
* `POST /admin/invoice` — создание и привязка новой сущности `Bill` к выбранному пользователю.
* `DELETE /admin/users/delete/{id}` — каскадное удаление пользователя и всех связанных с ним счетов/показаний из базы данных SQLite.
* `POST /admin/news/create` — публикация новостей ЖКХ.
* `POST /admin/outages/create` — фиксация проведения аварийных или плановых технических работ на сетевых узлах.
